Preferred method

Pre-selects Face or PIN when the credential dialog opens. Best-effort: it needs the dialog to expose its method switcher, which not every state does.

Lock screen stays on Face

Windows resets the sign-in default to whatever you used last. The app re-asserts Face every 15 seconds, so the next logon starts on the camera, not the PIN pad.

What actually changes

The honest version

For passkey (WebAuthn) sign-ins and similar operations, that click is how Windows records that a human deliberately approved this specific request. With this utility running, any Windows Hello prompt raised while your face is recognized is approved without a deliberate click from you.

What does not change

The limits

Your face still has to be recognized first. The app cannot approve anything for a person the camera does not recognize, and it never enters, reads, or stores a PIN, a password, or biometric data. It presses a button that Windows has already decided to offer you.

When to skip it

Fair warning

If other people use the machine, or if you want a moment to read what each prompt is asking before it is approved, this is not for you. You can also install it and leave auto-click off, keeping only the sign-in-method and lock-screen features.

Why it asks for Administrator.

Two reasons, both structural rather than optional.

The credential dialog

Integrity level

The "Windows Security" dialog runs elevated. Reading and activating a control inside it requires a process at the same level, so a standard-privilege build could not press anything.

The sign-in default

HKEY_LOCAL_MACHINE

Keeping the lock screen on Face means writing LastLoggedOnProvider under HKEY_LOCAL_MACHINE, which standard users cannot write.

No prompt at each logon

Scheduled Task

Setup can register a logon task with the highest run level, which starts the app elevated at sign-in without a UAC prompt. Uninstalling removes the task.

It is not code-signed.

SmartScreen will warn on first run, and that warning is doing its job.

An unsigned program that immediately asks for administrator rights and interacts with the Windows credential interface is exactly the shape of thing worth being suspicious of. What is offered instead of a signature is the SHA-256 checksum published with every release, so you can confirm that the file you downloaded is the file that was published. Run this and compare it with SHA256.txt on the releases page:

Get-FileHash .\WindowsHelloAutoClick-Setup.exe -Algorithm SHA256
